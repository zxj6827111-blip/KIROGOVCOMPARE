# 解析错误处理指南（PostgreSQL 版）

## 适用范围
本指南仅适用于当前 PostgreSQL 架构，不再包含 SQLite 处理方式。

## 快速诊断
1. 先判断是 LLM 解析问题还是原始 PDF 数据问题。
2. 再决定是手动修正 `parsed_json`，还是触发重解析。

## 方案一：手动修正 parsed_json（推荐）

适用场景：
- 小范围字段错误
- 原因明确（OCR 误识别、字段映射偏差）

示例脚本（`scripts/fix-report-{id}.js`）：

```javascript
const pool = require('../dist/config/database-llm').default;

async function main() {
  const versionId = 25; // 替换为实际 version_id

  const versionRes = await pool.query(
    'SELECT parsed_json FROM report_versions WHERE id = $1 LIMIT 1',
    [versionId]
  );
  const row = versionRes.rows[0];
  if (!row) throw new Error('version_not_found');

  const parsed = typeof row.parsed_json === 'string'
    ? JSON.parse(row.parsed_json)
    : row.parsed_json;

  // 按需修正
  const table4 = parsed.sections.find((s) => s.type === 'table_4');
  table4.reviewLitigationData.litigationDirect.other = 10;
  table4.reviewLitigationData.litigationDirect.total = 12;

  await pool.query(
    'UPDATE report_versions SET parsed_json = $1 WHERE id = $2',
    [JSON.stringify(parsed), versionId]
  );

  await pool.end();
  console.log('OK: parsed_json updated');
}

main().catch(async (err) => {
  console.error(err);
  await pool.end();
  process.exit(1);
});
```

执行：

```bash
node scripts/fix-report-{id}.js
```

```bash
curl -X POST http://localhost:8787/api/reports/33/checks/run

```

## 方案三：重新触发解析

适用场景：
- 错误范围较大
- 需要完整重跑解析链路

建议通过系统已有重解析接口触发，不直接手工删表数据。

## 最佳实践
1. 小问题优先手动修正，成本最低。
2. 每次修正保留脚本或 SQL 记录，便于审计。
3. 修正后必须重新跑一致性校验。
4. 若同类问题频发，再优化提示词与结构化规则。
